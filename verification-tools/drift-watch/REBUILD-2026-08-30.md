## ⚠️ CORRECTION TO MY OWN EARLIER REPORT

An earlier revision of this file stated: *"Recorded toolchain equalled installed toolchain (1.77.2)
in every single case."* **That was false.** Only 2 of the 7 matched. **Five

## THE TOOLCHAIN FINDING — the commercially significant line

**7 of the 8 reproductions crossed a toolchain mismatch**, spanning
**1.76.0 → 1.77.3**, including `agent_id` across a full minor version and
`a2a_escrow` at 3,423 lines across four modules.

Move bytecode output was stable across that range for these packages. **A
recorded toolchain is evidence of hygiene, not a precondition for a
trustworthy comparison.**

**The rule, adopted:** a toolchain mismatch is a reason to double-check a
divergence before reporting it — **never** a reason to refuse to watch a
package.

**Not proven:** that toolchain never matters. This band is 1.76.0–1.77.3. A
wider gap, a framework-dependency bump, or a different `build-config` flavour
could still diverge. The `pin` gate's reasoning stands; its effect is
measurably smaller than assumed within this range.

## THE DIVERGENCE — real drift in our own code

`projectx-raffle/sui-contracts` module **`raffle_v1`**: local 7,526 bytes,
deployed 7,482 — 44 bytes longer locally. `fenwick` in the same package
reproduces exactly, so this is neither toolchain nor normalization.

Characterised:
- sources committed and clean;
- local build digest `0426e5877b1ac21401fdfc03a2699997ac285d36190faf600ecdf0c8032b80a4`
  **exactly matches the repo's own `ci-expected-digest`** — the local build is
  correct;
- the function `create_raffle_v2` **is already deployed** (verified in the
  on-chain identifier table by the engineering desk). The unpublished thing is
  **one guard added inside an already-live function**, not a new feature.
  *(An earlier version of this report said "a feature was committed and never
  published". That was wrong and is corrected here.)*
- three commits have touched the source since publish, not one; two are
  `#[test_only]`, which Move strips from published bytecode, so they explain
  none of the 44 bytes.

**Conclusion: source ahead of chain.** Benign — unshipped development, not
tampering.

## WHY THAT DIVERGENCE IS THE PRODUCT DEMONSTRATION

**That repo's existing `digest-guard` gate is GREEN right now.** It compares
the build digest against a committed expectation — both sides local. It is
structurally incapable of noticing the chain holds something else.

On our own mainnet contract today: **existing CI gate PASS, deployed reality
44 bytes different.** That gap is the entire product, measured on ourselves
rather than asserted in a pitch.

## Liveness — a recorded address is not a live package

Both t2000 addresses were confirmed live before comparison (version 13, 4
modules; version 3, 1 module — matching their records). This is now a
first-class check in the tool, because `probe` and `comp-probe` in
`projectx-raffle` both record mainnet addresses that **do not resolve**. A
census trusting `Published.toml` alone would report two phantom deployments.

## The one stated normalization
`sui move build` emits a package's self-address as 32 zero bytes; the address
is fixed at publish. We substitute 32-zero-byte runs in the LOCAL bytes with
`original-id`, and nothing else. Evidence it is sound: `fenwick` differed in
exactly 30 bytes at one offset where local held zeros and the chain held
`44a9e92e005b9375…`; after substitution it is byte-identical.

## Limits — stated, not buried
- 9 packages, 7 of them ours. Not an ecosystem sample.
- Same machine, same install throughout. Nothing here proves a *different*
  1.77.2 environment reproduces identically.
- One divergence correctly characterised is not proof that every divergence
  will be.
- **Chain half INDEPENDENTLY CONFIRMED 2026-08-30** by the engineering desk,
  which queried both t2000 addresses itself: `0x912b6fe2…` live at version 13
  with 4 modules (`batch, escrow, opening, reputation`), `0xe94a8b8f…` live
  at version 3 with 1 module (`registry`) — matching the figures reported
  here. **The BYTECODE COMPARISON remains single-sourced**: the
  t2000 source was a scratchpad clone that no longer exists, so it could not
  be independently rebuilt. That half stays unverified and labelled until it
  can be. The t2000 checkout is ephemeral (a scratchpad clone of
  `github.com/mission69b/t2000` at `c2c0ce8`); anyone re-running must clone it
  fresh. The addresses above make the chain half independently checkable.
